# 对话缓存

可信 harness 把从会话日志派生出的对话按派生名存成对话缓存，绑定到日志位置 N；之后读这份缓存，再读 N 之后的事件，就能还原对话。缓存覆盖的事件变得不可读时，缓存过期。

Status: shipped

## Behavior

- Who: 可信 harness，以 `ContextAccess` 提供 owner、actor 和 scope。
  - 保存和删除对话缓存需要 System 或 Operator。
  - 保存、查找、列出和读取都需要能读到缓存覆盖的每个事件：会话的 scope，加上位置 N 及以前的事件追加时各来源所在的 scope。保存者读不到的事件不会出现在它派生的对话里，所以它也不能替这些事件保存缓存。
  - access 绑定了 session 时，只能保存、查找、列出、读取和删除这个会话的缓存。
- Entry: `store.session_log(access)` 句柄上的 `save_conversation_cache`、`conversation_cache`、`conversation_caches`、`read_conversation_cache` 和 `remove_conversation_cache`，派生开始前用同一句柄的 `availability_epoch` 取得可用性 epoch。会话先按[会话头、会话列表与 fork](sessions.md)创建或 fork 出来。
- Does: 对话缓存是 harness 从[会话日志](session-log.md)位置 1..N 派生出的完整对话，绑定到位置 N，存放在会话模块。对话的派生规则属于 harness，MMDB 不解释缓存的内容。
  - 派生名：每份缓存带一个 harness 定义的派生名和媒体类型。一个会话的每个派生名只保留最新一份；用同一派生名的 harness 可以复用彼此的缓存。
  - 保存：`save_conversation_cache` 接受会话、派生名、位置 N、媒体类型、派生开始前取得的可用性 epoch 和载荷的输入流。载荷完整写入后，新缓存替换同一派生名下原有的缓存，不论原有缓存的位置在前还是在后。N 可以落在 fork 继承的前缀里。
  - 查找与列出：`conversation_cache` 按会话和派生名取一份缓存；`conversation_caches` 返回一个会话中读者可读的缓存，每项给出派生名、版本、位置、媒体类型、字节数、摘要、保存时间、保存者的来源身份，以及是否过期。
  - 读取：`read_conversation_cache` 按查找或列出得到的版本和偏移翻页读取一份未过期缓存的载荷。harness 恢复对话时，读完缓存再从 N+1 起翻页读会话日志，把之后的事件交给自己的派生规则。
  - 过期：位置 N 及以前的任何事件被撤回或清除，或因所在的消息被撤回或清除而不可读，缓存就过期。撤回或清除其中的事件；撤回或清除 N 之后的片段或工具调用，使一条在 N 及以前开始的消息整条不可读；在来源会话里撤回或清除 fork 共享的前缀事件，都会让覆盖它的缓存过期。
  - 仍然有效：N 之后的事件被撤回或清除而不牵连 N 及以前的事件、其他记录的修订推进可用性 epoch、重置记忆、重开存储时收尾轮次，缓存都仍然有效。
  - 删除：`remove_conversation_cache` 删除一个派生名下的缓存；这个派生名下没有缓存时什么也不做。
  - fork 出的会话不带来源会话的缓存，harness 可以另为它保存。
- Fails:
  - 保存被拒绝时什么也不写：调用方不是 System 或 Operator；会话不存在或读者不可访问；派生名或媒体类型不合法；N 为 0 或超过会话当前位置；给定的可用性 epoch 大于当前值；保存者读不到覆盖的某个事件；在给定的可用性 epoch 之后，位置 N 及以前有事件被撤回或清除，harness 取得新的 epoch 重新派生。
  - 保存和删除不带操作 ID。提交结果未知时 harness 再保存或删除一次：同一内容重复保存只是再替换一次。
  - 保存中途中断时原有缓存不变，写了一半的载荷由 `recover_payloads` 有界清理。
  - 读取已过期缓存的载荷报已过期；翻页期间缓存被替换或删除，报已被取代，harness 重新列出。
  - 读者缺少覆盖事件所需的某个 scope 时，查找和读取被拒绝访问，列表也不返回这份缓存。
  - 这个 feature 之前创建的存储没有记下事件的来源 scope 和撤回位置，打开时被拒绝，需要整库重置，不做迁移。
- Limits: 派生名和媒体类型 1–256 字节，不含控制字符。载荷按 32 KiB 分块并校验摘要，单次读取最多 1 MiB。缓存大小和每个会话的派生名数量不设上限；每次保存整份重写，读取输入流期间持有存储的写锁，与追加事件相同。列表每页 1–100 份，以游标翻页。判断过期的开销随会话的 fork 链长度和缓存保存之后的撤回次数增长，与日志长度无关。
- Keeps: 缓存保留到被替换、删除或整库重置，重置记忆不影响它。过期缓存的载荷立刻不可读，磁盘空间由 `recover_payloads` 有界回收；在被替换或删除前，列表里仍显示为过期。被替换或删除的缓存载荷同样由 `recover_payloads` 回收。对话缓存不是记录：没有 pin，不能作为对象、关系、日志事件或检查点的来源，也不进搜索。保存或删除缓存不推进会话变更号。

## Decisions

### 对话缓存放在 MMDB 的会话模块

MMDB 是 agent 所有数据的统一数据层：n 个 harness 接入同一存储，对话和状态、日志、记忆一样是这一层的数据，能在这一层迁移和流动，数据仍按 owner 和 scope 隔离。会话模块也是唯一知道哪个位置以前的事件被撤回或清除的地方。

- Rejected: harness 把派生出的对话存在自己的运行状态里，按 era、日志位置和可用性 epoch 作废，在只有一个 harness 接入、派生结果只对它自己有意义时更好。
- Wrong-call signal: MiuMiu 接入后仍保留自己的副本或仍从头派生；或读到的缓存几乎总是已过期。

### 每个派生名只留最新一份

同一会话会被不同 harness、不同模型请求格式各自派生，派生名把它们分开，也是 harness 之间复用缓存的约定；恢复只需要位置最靠后的一份。

- Rejected: 每个会话一份缓存，在只有一个 harness、一种格式时更好；同一派生名按位置保留多份，在经常要恢复到较早位置时更好。
- Wrong-call signal: harness 为了恢复到较早的位置而从头派生。

### 读取要求能读到覆盖的每个事件

读缓存所需的 scope 与读它覆盖的事件相同：会话的 scope 加上位置 N 及以前的事件各来源的 scope。凡是能自己从日志派生出同样对话的读者都能读缓存，其他读者读不到；scope 各不相同的 harness 共用一个存储时，这条规则不会把本可读到全部事件的读者挡在外面。

- Rejected: 要求保存者 access 的全部 scope，在所有读者都用同一个 access 时更好，实现也更简单。
- Wrong-call signal: 读缓存时检查 scope 的开销明显超过读载荷本身。

### 只有位置 N 及以前的事件不可读时才过期

撤回或编辑最近一条消息很常见；按会话作废，每次编辑都要从头派生，等于没有缓存。会话模块知道每次撤回或清除让哪个位置以前的内容不可读，包括整条消息和 fork 共享的前缀。

- Rejected: 会话或它继承的前缀里任何撤回或清除都算过期，在撤回很少、而实现必须一眼可证不会漏判时更好。
- Wrong-call signal: 清除一条事件后，从未过期的缓存还原的对话里仍能看到它的内容。

### 过期后立刻不可读，空间有界回收

过期缓存可能含有已清除的内容，所以载荷立刻不可读；磁盘空间与清除的载荷一样由 `recover_payloads` 有界回收。撤回或清除一条事件的开销因此与受影响的缓存有多大、有多少份无关。

- Rejected: 在撤回或清除的同一批次里删掉受影响的缓存，在操作者要求清除后内容立刻离开磁盘时更好。
- Wrong-call signal: 清除很久之后，过期缓存仍占着磁盘，因为没有人调用 `recover_payloads`。

### 只从会话日志派生

位置 N 的缓存是日志 1..N 派生出的完整对话；检查点摘要和窗口裁剪属于 harness 组装窗口。缓存因此只随日志事件过期；放进检查点摘要，就要随摘要的来源过期，否则清除记忆后摘要里的内容会从缓存漏出。

- Rejected: 允许缓存以检查点为起点，在完整对话大到每次保存都重写不起时更好。
- Wrong-call signal: harness 因为完整对话太大而放弃缓存，改回检查点加日志尾部。

### 不设大小和数量上限

缓存与日志事件载荷一样不限大小，每个会话的派生名也不限数量；保存频率由 harness 决定。

- Rejected: 每份最多 64 MiB、每个会话最多 8 个派生名，在大缓存的写入明显阻塞其他写入时更好。
- Wrong-call signal: 保存大缓存时同一存储的其他写入明显卡顿；或派生名越积越多，因为 harness 把规则版本写进了派生名。

### 不推进会话变更号

会话列表反映交互本身。harness 常在每个轮次结束时保存缓存，推进会话变更号会让同步方把没有新交互的会话当成有变化；缓存本来就能从日志重建。

- Rejected: 保存或删除缓存推进会话变更号，在其他 harness 靠会话列表发现新缓存时更好。
- Wrong-call signal: 同步方为了取到新缓存，只能定期列出每个会话的缓存。

### 对话缓存不是记录

缓存随时会被替换或过期，作为来源会让引用指向一份随时消失的副本；要引用原文就引用日志事件。缓存因此没有 pin，不进搜索，保存和删除也不带操作 ID：同一内容重复保存只是再替换一次，不需要回执来确认。

- Rejected: 像检查点一样作为有 pin 和修订的记录，在需要引用模型某次看到的确切对话时更好。
- Wrong-call signal: harness 需要证明模型某次看到的对话，而日志位置加派生名不足以重现它。

### 派生期间覆盖的事件失效时拒绝保存

保存时比对派生开始前取得的可用性 epoch：之后位置 N 及以前有事件被撤回或清除，保存被拒绝，harness 马上知道要重新派生。其他记录的修订推进 epoch 不影响保存。

- Rejected: 照常保存但立刻标为过期，在保存绝不能失败时更好。
- Wrong-call signal: 撤回频繁的会话里，保存一再被拒绝，harness 始终存不下缓存。

## Not this

- MMDB 定义或解释对话格式与派生规则。
- 缓存里放检查点摘要或其他不从会话日志派生的内容；窗口的选择与裁剪。
- 同一派生名按位置保留多份缓存。
- fork 时复制缓存。
- 把缓存作为来源，或搜索缓存的内容。
- 增量追加缓存；每次保存整份重写。
- 缓存过期后由 MMDB 自动重新派生。
- 通过会话变更号发现新缓存。
