# 会话头、会话列表与 fork

可信 harness 先创建带会话头的会话再写它的会话日志，按会话变更号从新到旧列出会话，并能从一个会话日志的某个位置 fork 出新会话；新会话的日志以这段前缀开头，与来源共享其中的事件。

Status: decided

## Behavior

- Who: 可信 harness，以 `ContextAccess` 提供 owner、actor 和 scope。
  - 创建会话、fork、修改会话头和列出会话都需要 System 或 Operator。
  - access 绑定了 session 时，只能创建或 fork 出这个会话。
  - 创建子会话需要读者能访问父会话的 scope；fork 需要读者能访问来源会话的 scope。
- Entry: `store.session_log(access)` 句柄上的 `create_session`、`fork_session`、`update_session`、`session` 和 `sessions`。会话必须先创建或 fork 出来，才能向它的[会话日志](session-log.md)追加事件。
- Does: 会话由会话头和会话日志组成，都在会话模块里。会话头记下创建时就固定的会话 ID、类型、scope 和创建时间；子会话还记下父会话和父 run，fork 出的会话还记下来源会话和位置。类型是 harness 定义的名称，会话头另带一段 harness 定义的元数据，例如标题；MMDB 不解释这两者。
  - 创建：`create_session` 写入会话头，会话日志从序号 1 开始。父会话必须属于同一 owner 且读者可访问；子会话的 scope 可以与父会话不同。父 run 照原样记下，MMDB 不校验它。
  - 读取会话头：`session` 返回会话头的当前修订，以及 MMDB 维护的日志位置、轮次数、当前未结束轮次的 run、最后变更时间和会话变更号。
  - 列出：`sessions` 按会话变更号从新到旧排列，以游标翻页，可以按类型或父会话过滤，只返回读者 scope 可访问的会话，每项与 `session` 返回的内容相同。对会话的任何写入都推进它的会话变更号：创建、修改会话头、追加事件（包括轮次和步骤的边界与补齐的事件）、撤回或清除它自己的事件，以及重开存储时收尾它的轮次。harness 增量同步时从最新往回读，读到不大于上次见过的会话变更号即停。
  - 修改：`update_session` 凭预期修订替换元数据，产生新修订。类型、scope、父会话和 fork 来源不能改。
  - fork：`fork_session` 从来源会话的位置 P 创建新会话，scope 与来源相同。新会话在位置 1..P 读到来源的原事件：pin 相同，事件头里的 session 仍是事件发生时的会话。新事件从 P+1 编号，轮次号和步骤号接着来源在 P 处的编号。前缀中已有的事件 ID 在新会话里已被占用。工具调用、消息和轮次的身份查找只看 P 及以前的前缀，来源在 P 之后写入的事件对新会话不可见。
  - 截断的轮次：来源在 P 处有未结束的轮次时，同一批次在新会话里补齐收尾并以 Forked 结束这个轮次，补齐方式与取消相同，见[会话日志](session-log.md)。来源会话不受影响：它的轮次照常进行，会话变更号也不推进。
  - fork 出的会话也可以同时是子会话，例如带着父会话的历史派出的子 agent。
  - 子会话和 fork 出的会话照常追加事件、开启和结束轮次，重开存储时照常收尾。
- Fails:
  - 违反下列规则的调用被拒绝，什么也不写：调用方不是 System 或 Operator；名称不合法或元数据超长；父会话或来源会话不存在、属于另一 owner 或读者不可访问；P 不在 1 到来源当前位置之间；fork 链超过上限。
  - 同一操作同内容重试返回原回执；同一会话 ID 已存在而内容不同时报冲突。
  - fork 的会话头和补齐在同一批次提交，进程中途退出时这次 fork 整体没有发生。
  - 向没有会话头的会话追加被拒绝，错误说明会话不存在。向 fork 出的会话追加前缀中已有的事件 ID：内容相同时取回原事件的回执，内容不同时报冲突。
  - `update_session` 的预期修订与当前修订不符时什么也不改。
  - 前缀中已撤回或清除的事件，在 fork 出的会话里保持同样的状态。
  - 这个 feature 之前创建的存储没有会话头，打开时被拒绝，需要整库重置，不做迁移。
- Limits: 元数据是不超过 4 KiB 的 JSON。会话 ID 和类型名 1–256 字节，不含控制字符。列表每页 1–100 个会话，每页最多扫描 4,096 条索引；带过滤时一页可能不满或为空，仍带游标。fork 链最多跨 64 个会话；fork 的位置落在来源自己继承的前缀里时，新会话直接引用更早的会话，不增加层数。超过上限时，harness 以派生出的对话新建会话。fork 的开销取决于截断轮次里未终止的消息和欠着结果的调用，与前缀长度无关。
- Keeps: 会话头保留到整库重置，重置记忆不影响它；只保留当前修订，旧修订的 pin 读作已被取代。会话变更号单调递增，不复用。fork 出的会话一直引用来源的事件；清除前缀中的一条事件后，所有共享它的会话都读不到它。

## Decisions

### MMDB 维护会话头、会话列表与 fork

会话头、会话列表和 fork 放在会话模块，不由各 harness 在运行状态里各管一份会话目录。另一个 harness 不读 MiuMiu 私有的命名空间，也要能找到会话以及会话之间的父子与 fork 关系；截断的轮次只能由 MMDB 以 Forked 结束，harness 靠追加做不到。

- Rejected: 每个 harness 在运行状态里维护会话目录，fork 由 harness 逐条追加事件，在会话目录只对一个 harness 有意义、且运行状态已能与日志追加同批提交时更好。
- Wrong-call signal: MiuMiu 接入后仍保留自己的会话目录，两份目录出现不一致，例如某个会话只出现在其中一份列表里。

### 会话先创建再追加

类型、scope、父会话和 fork 来源要在会话出现的那一刻固定，所以向会话日志追加前必须先创建或 fork 出会话。隐式创建会留下没有会话头的会话，每个读者都要另外处理。项目处于 startup，接入方随之调整调用。

- Rejected: 第一次追加时隐式创建、之后再补会话头，在接入方很多、改调用代价大时更好。
- Wrong-call signal: harness 每次追加前都要先「确保会话存在」，多一次往返。

### fork 共享前缀，不复制

fork 出的会话在 1..P 读到来源的原事件。清除前缀中的一条事件，它就从所有共享它的会话里消失，与「要抹掉就清除那条日志事件」一致；fork 的开销只取决于截断的轮次，而带父历史派子 agent 时，常在父轮次进行中 fork。

- Rejected: 把前缀的事件和载荷复制成新会话自己的事件，在 fork 少且前缀短、或 fork 出的会话要在来源被清除后继续保留时更好。
- Wrong-call signal: 用户清除来源会话中的内容后，要求它在 fork 出的会话里保留；或读取 fork 出的会话的代码，因为事件头写着另一个会话而出错。

### fork 出的会话与来源同 scope

前缀中的事件属于来源会话的 scope，fork 出的会话换用别的 scope，等于让另一范围的读者读到这些事件。子会话不共享事件，所以它的 scope 可以与父会话不同。

- Rejected: fork 时可以选择别的 scope，在前缀只含公共内容、要把它带进另一个工作区时更好。
- Wrong-call signal: harness 为了把一段会话带进另一个工作区，只能逐条复制事件。

### 类型和元数据由 harness 定义

类型是 harness 定义的名称，标题这类字段放进 harness 定义的元数据，MMDB 都不解释。MMDB 不按类型或标题改变行为，而各接入方的会话种类和展示字段不同，例如 MiuMiu 有聊天、子 agent、工作内容和工作领取几类会话。

- Rejected: MMDB 内置会话类型枚举，如主会话、子 agent、脚本，在 MMDB 要按类型改变行为时更好；MMDB 提供固定的 title 字段，在 MMDB 要按标题搜索时更好。
- Wrong-call signal: MMDB 里出现判断类型名的代码；或两个 harness 必须约定元数据的键名，才能显示对方的会话列表。

### 列表只按会话变更号从新到旧

一种顺序同时满足界面按最近活动排序和增量同步：从最新往回读，到上次见过的会话变更号为止。列表里每个会话只有一行最新状态。

- Rejected: 另提供从会话变更号 N 之后升序读的变更流，在同步方要逐条重放每次变更时更好。
- Wrong-call signal: 同步方需要知道某个会话中间的一次变更，而列表只给出最新状态。

### 会话头只保留当前修订

修改会话头凭预期修订比对，旧修订不保留。标题常摘自第一条用户消息，保留旧修订等于留下一份不能清除的原文副本。

- Rejected: 保留会话头的每个修订，在需要审计会话头的修改记录时更好。
- Wrong-call signal: 有人要求查出会话改名前的标题。

## Not this

- 删除会话或会话头。
- fork 时复制检查点或对话缓存；fork 出的会话从没有检查点开始。
- 把 fork 出的会话合并回来源。
- 校验父 run，或追踪 run 的生命周期。
- MMDB 解释类型或元数据，例如按标题搜索。
- 逐条重放每次变更的变更流。
- 保留会话头的旧修订。
- 修改会话的 scope、owner、类型、父会话或 fork 来源。
- 按 fork 来源过滤列表。
