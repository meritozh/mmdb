# 连续会话日志与原文搜索

可信 harness 把一个会话的用户消息、assistant 消息、工具调用与结果和通知按序追加到会话日志，并用轮次和步骤标出它们属于哪次输入、哪次模型请求；之后可以翻页、搜索原文、固定版本并作为新对象的来源。结束的轮次里每条消息都已终止、每个工具调用都有结果，崩溃留下的轮次在重开存储时补齐并标为中断。即使 agent 当时没有整理某段交互，重置记忆后这段日志仍完整可读。

Status: shipped

## Behavior

- Who: 可信 harness，以 `ContextAccess` 提供 owner、actor、scope 和来源 agent、session、run。
  - access 绑定了 session 时，只能追加该会话的事件。
  - 用户消息只能由 User、System 或 Operator 写入；轮次和步骤的开始与结束只能由 System 或 Operator 写入；列出会话需要 System 或 Operator；撤回或清除日志事件需要 User 或 Operator。
  - 开启轮次的可以是发模型请求的 agent，也可以是脚本、API 或事件监听这类不发模型请求的一方。开启轮次的 access 必须带 run，轮次记下这个 run，轮次里的步骤事件、assistant 事件、工具调用和结果，以及轮次的结束，只接受这个 run 写入，结束事件以开启事件的 ID 指明它结束的轮次；这个 run 启动的工作，例如工具调用启动的图，以这个 run 的身份写入。别的一方要调用工具，就像来了一条新的输入，在这个轮次结束后开启自己的轮次。
  - 重置记忆由持有存储租约的进程发起，凭计划的确认摘要提交。
- Entry: `Store::create(path)` 创建存储，`Store::open(path)` 重开，再以 `store.session_log(access)` 取得会话日志句柄，[检查点](context-checkpoints.md)也在这个句柄上。轮次和步骤的开始与结束和其他事件一样用追加写入。句柄上的方法名使用术语表的词，不带 history。
- Does: 会话日志和检查点存放在会话模块，与记忆模块同在一个存储，共用租约和批次提交。切换模型窗口仍追加到原会话的日志。MMDB 在写入时分配单调递增的序号，以及会话内递增的轮次号和步骤号；时间戳描述事件时间。
  - 追加：接受稳定事件 ID、可选预期位置、输入流及来源。完整写入后，事件头、序号、索引和回执一起发布。同一事件同内容重试会取回原序号，即使后面已经追加其他事件；同一身份提交不同内容会冲突。
  - 轮次与步骤：一个会话同时最多一个未结束的轮次，一个轮次同时最多一个未结束的步骤，轮次可以没有步骤。轮次未结束期间追加的事件，MMDB 在事件头里记下所在的轮次号和步骤号，harness 不必传。assistant 事件只能写在未结束的步骤里；assistant 消息发出的工具调用只能写在这条消息所在、尚未结束的步骤里；不关联 assistant 消息的工具调用只要求有未结束的轮次，可以不在步骤里。工具结果和它的调用在同一步骤，调用不在步骤里时在同一轮次。用户消息和通知在轮次内外都可以写。
  - 消息：assistant 的开始、有序片段和终止事件共用消息 ID。撤回或清除其中一个事件后，整条消息及其余片段都不能再用来重现原文。工具结果必须关联同一会话中唯一的调用；调用不可读时，结果也不可读。轮次还欠着结果的调用即使已被清除或所在的消息已被撤回，结果照样可以写入，写入后随调用不可读。
  - 结束：步骤结束前，其中的 assistant 消息必须都已终止、工具调用必须都有结果。轮次以 Completed、Cancelled、Failed、Interrupted 或 Forked 结束，更细的原因（如 blocked、max-tokens、取消来源、错误详情）放在结束事件的载荷里。以 Completed 结束时不能有未结束的步骤或没有结果的工具调用。Interrupted 只由重开存储写入，Forked 只由 fork 写入。
  - 补齐：轮次以 Cancelled、Failed、Interrupted 或 Forked 结束时，MMDB 在同一批次里按顺序补齐收尾：没有终止的 assistant 消息补一个 Interrupted 终止，没有结果的工具调用补一条 outcome 为 EffectUnknown、载荷为空的结果，未结束的步骤补一个结束事件，最后写轮次结束。补齐的事件由 System 以轮次的 run 写入，事件 ID 是确定的，以 `mmdb:` 开头；harness 写入的事件 ID 不能用这个前缀。harness 知道确切结果时先自己写，例如工具还没派发就写 RejectedBeforeDispatch。给模型看的说明文字由 harness 在派生对话时按 outcome 生成。
  - 来源：日志事件可以把记忆模块中的记录作为来源，对象和关系也可以把日志事件作为来源。追加时来源必须可读，工具结果对它所还的调用除外；复制可读的旧修订时登记来源，独立观察可以不带外部来源。日志事件写入后只读：能否读取只取决于它自己、所在的消息和关联的工具调用，来源之后的修订、撤回、清除或重置都不改变它。读取时仍需要追加时各来源所在的 scope，复制不会放宽可读范围。当前可用性检查照常沿来源跨模块进行。要从历史中抹掉内容，就清除那条日志事件，以它为来源的对象、关系和检查点随之不可用。
  - 读取：按日志位置定位和翻页，事件头带轮次号和步骤号，翻页即可按轮次和步骤分组；按 pin 读取载荷，列出会话，为恢复取得工具调用与结果的配对。恢复时读已有日志，只追加新产生的交互。
  - 搜索：返回匹配事件的固定引用、首个匹配的字节位置和续查游标。跨会话按键序、同会话按序号遍历，子串可以跨存储块和查询页。ASCII 匹配忽略大小写，中文按 UTF-8 字节匹配。未命中且仍有游标时可以继续扫描。
  - 重置记忆：先取得计划，计划给出要重置的记忆模块、新旧 era、过期时间和确认摘要，再凭完整摘要提交。一次提交让记忆模块换新 era，旧记录立刻不可见；磁盘空间由有上限、中断后能接着做的清理回收，不留隔离副本。记忆模块包括原生记忆，以及领域上下文的类型、对象、关系、业务动作定义与执行记录。会话模块不受影响。
  - 重置记忆之后：日志事件和载荷照常可读，指向旧记忆的来源显示为已重置。这些事件在当前可用性检查中也照常可用：指向旧记忆的来源是检查的终点，不阻断检查，直接引用旧记忆本身才报已重置。重置前保存的检查点载荷仍可读，但不能用于当前恢复，harness 从它记录的日志位置重新生成。
  - 整库重置：旧目录移到隔离路径，所有模块换新 era。
- Fails:
  - 违反轮次和步骤规则的追加被拒绝，什么也不写，错误指明违反的是哪条规则，harness 据此把撞上别人轮次的外来调用排队：不带 run 开启轮次；在步骤之外写 assistant 事件；在消息所在的步骤之外写它发出的工具调用；在轮次之外写工具调用或工具结果；工具结果与它的调用不在同一步骤或同一轮次；已有未结束的轮次或步骤时再开一个；由别的 run 写入轮次里的步骤、assistant 事件、工具调用、结果或轮次结束；结束事件指明的不是当前未结束的轮次；步骤里还有未终止的消息或没有结果的调用时结束步骤；以 Completed 结束还有未结束步骤或没有结果的调用的轮次；harness 写 Interrupted 或 Forked。
  - 进程在轮次中途退出时，下次 `Store::open` 在同一批次里把未结束的轮次以 Interrupted 结束，补齐方式与取消相同。租约保证一次只有一个进程持有存储，所以打开时没结束的轮次都属于已退出的进程；同一进程放掉句柄再重开，它自己没结束的轮次也会这样结束。
  - 重置记忆之前的记忆引用读作不可用：已重置，与已清除区分。另一 owner 或另一存储的引用被拒绝访问，整库重置之前的引用也算另一存储。
  - 追加中断不推进日志位置，`recover_payloads` 有界清理未完成的载荷。
  - 重置记忆要么整体生效，要么没有发生；没做完的清理在下次打开时继续。确认摘要不符或计划过期时不做任何改变。
  - 旧格式的目录，包括 `mmdb-context-v1`，打开时被拒绝，需要整库重置，不做迁移。
- Limits: 载荷按 32 KiB 分块并校验摘要。单次读取载荷最多 1 MiB。单次搜索最多扫描 4,096 个事件或 16 MiB。工具调用追加时，来源检查为它的结果预留一层深度和一次访问，所以调用一定能写入结果。读取输入流期间持有存储的写锁，长时间不结束的流会阻塞同一存储的其他写入。打开存储时收尾的耗时随未结束轮次的数量增长，每个会话最多一个，不扫描全部会话。
- Keeps: 日志事件，包括轮次和步骤的开始与结束、补齐的事件，以及载荷和检查点，保留到被清除或整库重置，重置记忆不影响它们。撤回或清除轮次和步骤事件，不改变其他事件已记下的轮次号和步骤号，也不重新打开或关闭轮次。旧记忆的分区由清理删除，不留隔离副本；最近写入的内容还留在存储引擎共用的预写文件里，等它轮转后才释放，所以重置记忆不是安全擦除。

## Decisions

### 会话日志是同一存储里的独立模块

会话日志和检查点放进会话模块，与记忆模块同在一个存储。会话日志是交互的唯一来源，重置记忆后重建记忆正需要它；同一存储让清除、可用性 epoch 和记录变更同批提交，运行状态之后也能与日志追加同批提交。

- Rejected: 维持日志和检查点随记忆一起重置，在操作者重置记忆就是要清空一切时更好；把日志放进独立目录，在日志与记忆之间永远不需要同批提交时更好。
- Wrong-call signal: 跨模块的可用性检查无法单向分层，必须读懂记忆模块的内部格式。

### 会话日志记录轮次和步骤

MMDB 记录轮次和步骤的边界，给其中的事件标上轮次号和步骤号，并在轮次没有正常完成时补齐收尾。崩溃后关闭未结束的轮次、让轮次的终止状态与结束事件同批落盘、原生记忆要求承诺类证据来自以 Completed 结束的轮次、按轮次查看耗时和错误、派生对话时每个工具调用都有结果、fork 时截断未结束的轮次，这六件事都要日志自己认得轮次边界；只记消息时，每个 harness 都要各写一遍。

- Rejected: 日志只记消息和工具事件，轮次由 harness 自己记录，在接入方的 agent loop 不是「一个会话一条线」、例如会话内有并行的模型请求时更好。
- Wrong-call signal: 第二个接入方必须改动 agent loop 的结构才能写进日志。

### 子运行用自己的会话

自己发模型请求的子运行用自己的会话：委派出的子 agent 和脚本编排的模型请求（如 Rhai 脚本里的 `agent()`）走同一种子会话，只是类型不同。轮次只接受开启它的 run 写入，所以一个会话始终是一条按序进行的对话，崩溃收尾和派生对话都不用按 run 拆分；dsh 的子 agent 和 Claude Code workflow 里的每个 `agent()` 也各有自己的记录。工具执行期间发出的调用以父 run 的身份写进父会话当前的步骤。

- Rejected: 子运行在父会话里各有自己的轮次，在父 agent 需要从一条日志读出子 agent 的全过程时更好。
- Wrong-call signal: harness 为了还原一个任务，不得不把父、子两条日志重新拼成一条。

### 不发模型请求的一方直接在轮次里调用工具

脚本、API、事件监听这类不发模型请求的一方，在会话日志看来是另一种 agent：它领取输入、开启轮次，在轮次里直接调用工具，不经过步骤。这样轮次结束和重开存储时的收尾照样覆盖这些调用，结束的轮次里每个调用都有结果，步骤仍只指一次模型请求。

- Rejected: 允许这类调用写在轮次之外，在发起方从不中途退出、配对总由它自己保证时更好；把步骤扩展为任意一方的一次请求，在需要把同一轮次里由不同请求发起的直接调用分开查看时更好。
- Wrong-call signal: 查看者要把一个轮次里的直接调用按发起它们的请求分组，而事件头里只有轮次号。

### 轮次只接受开启它的 run 写入

轮次里的步骤、assistant 消息、工具调用、结果和轮次的结束都只接受开启它的 run 写入。API、事件监听这类一方发来的直接调用就像一条新的输入，自己开启轮次；会话里还有别的 run 未结束的轮次时，开启被拒绝，由 harness 排队等它结束，或换用自己的会话。这个 run 启动的工作，例如工具调用启动的图或嵌套的图，以这个 run 的身份写入。访问里只带上一级 run，运行状态也不在存储里，MMDB 判断不了后代关系，所以由 harness 决定谁代表轮次写入，MMDB 只核对 run。这样取消一个轮次时补成 EffectUnknown 的调用都是它自己发起的，不会波及还在执行的外来调用。

- Rejected: 直接调用并入会话里正在进行的轮次，在一个会话只有一个写入方、外来调用撞不上别人的轮次时更好；按 run 的父子关系接受后代 run 写入，在事件需要记下真正发起调用的嵌套 run 时更好。
- Wrong-call signal: harness 为了不让外来调用排队，频繁把它们挪到另开的会话；或查看者要知道轮次里的调用出自哪个嵌套 run，而事件只记了开启轮次的 run。

### 结束事件指明它结束的轮次

结束轮次的事件以开启事件的 ID 指明它结束的轮次，对不上当前未结束的轮次就被拒绝。结束是轮次里影响最大的写入，会把还欠着的工作补成 EffectUnknown；一条没提交成功、之后又重试的结束事件，不能关掉后来开启的轮次，无论那个轮次属于别的 run 还是同一个 run。开启事件的 ID 由 harness 自己定，不必再向 MMDB 查询。

- Rejected: 任何 run 都能结束当前未结束的轮次，在操作台不知道轮次属于哪个 run 也要能取消时更好；只核对 run、不指明轮次，在同一个 run 从不重试过期的结束事件时更好。
- Wrong-call signal: harness 为了结束轮次，不得不先翻日志找开启事件的 ID。

### 打开存储时收尾崩溃留下的轮次

`Store::open` 在同一批次里把未结束的轮次以 Interrupted 结束。租约保证打开时没结束的轮次都属于已退出的进程，打开之后每个读者看到的都是配对完整的日志，不必各自推算。

- Rejected: harness 恢复某个会话时再补关，只读方当场推算而不写回，在多个进程同时写同一存储的不同会话时更好，在运行状态的终止状态无法与打开时的收尾同批提交时也更好。
- Wrong-call signal: 运行状态里已中断的 run 仍显示为运行中；或同一进程中途重开存储后，自己正在进行的轮次被标成 Interrupted。

### MMDB 补齐没有正常完成的轮次

以 Cancelled 或 Failed 结束轮次时，MMDB 在同一批次里补齐没有结果的调用、没有终止的消息和未结束的步骤；重开存储和 fork 走同一套收尾，规则只有一处。MMDB 只记 outcome，给模型看的说明由 harness 在派生对话时生成，因为对话的派生规则属于 harness。

- Rejected: MMDB 只检查、不代补，任何原因结束前都由 harness 先补齐，在 harness 要把给模型看的说明直接存进结果载荷、让日志不靠派生规则就能还原对话时更好。
- Wrong-call signal: 某个 harness 把空载荷的 EffectUnknown 结果当作工具的成功输出交给模型。

### 欠着结果的调用不可读时照样能写结果

轮次还欠着结果的调用被清除、或所在的消息被撤回之后，harness 和 MMDB 都照样可以写它的结果，结果写入后随调用不可读。否则这个轮次欠着一条谁也写不进的结果，只能以 Cancelled 或 Failed 结束；而先写结果再清除调用，结果同样不可读，先后顺序不该改变结局。

- Rejected: 只有 MMDB 补齐的结果能回应不可读的调用，harness 必须取消或失败这个轮次，在轮次中途清除内容就该中止轮次时更好。
- Wrong-call signal: 调用清除之后才写入的结果，能从搜索或派生对话中读到。

### 结束原因只分五种

轮次的结束原因只有 Completed、Cancelled、Failed、Interrupted 和 Forked，更细的原因放进载荷。MMDB 只按原因决定是否允许留下未结束的步骤、是否补齐以及谁可以写，这五种已经够用；名字与原生记忆的 `TerminalTurnStatus` 一致。

- Rejected: 把 blocked、max-tokens、取消来源等细分原因做成类型，在 MMDB 自己要按这些原因分别处理时更好。
- Wrong-call signal: MMDB 里出现必须解析结束事件载荷才能做的判断。

### 日志写入后只读

日志事件能否读取只取决于它自己、所在的消息和关联的工具调用，来源之后的修订、撤回、清除和重置记忆都不改变它。会话日志记录当时发生的交互，模型当时读到的记忆已经成为这段交互的一部分。原文通常本来就在用户消息或工具结果里，只清除记忆从来抹不干净历史；要抹掉，就清除日志事件本身，派生自它的对象、关系和检查点随之不可用。派生数据跟随来源，日志不跟随记忆，所以重置记忆既不会让日志失效，也不会让重置前的清除失效。

- Rejected: 清除记忆对象时，让复制了它的日志事件一起不可读，在记忆常常是某段内容在存储里唯一的副本时更好。
- Wrong-call signal: 用户清除一条记忆后，要求它的内容同时从会话日志消失，而逐条清除日志事件做不到。

### 入口是不以记忆命名的存储

`Store` 打开存储，再分别取得会话日志、领域上下文和原生记忆的句柄。继续用 `MemoryDatabase` 打开，等于让记忆拥有会话模块，与这次划出的重置边界相反，运行状态和记忆迁入时还要再改一次入口。

- Rejected: 在 `MemoryDatabase` 上挂会话日志句柄，在记忆始终是会话之外唯一的模块时更好。
- Wrong-call signal: `Store` 只剩转发调用，没有自己的行为。

### 只重置记忆时原地换 era

一次提交给记忆模块换新 era，旧记录由有界清理回收，不留隔离副本。同一引擎数据库中的多个 keyspace 无法通过一次目录改名整体隔离，复制副本要扫描整个记忆模块；隔离目录防的是重置错路径，而模块重置发生在受管存储内部。项目处于 startup，允许丢弃数据。

- Rejected: 先把记忆模块导出到隔离目录再换 era，在误重置经常发生、或操作者确实会从副本找回记忆时更好。
- Wrong-call signal: 有人要求找回误重置的记忆。

### 重置记忆后日志事件照常可用

复制了旧记忆的日志事件在重置记忆后照常可读，也照常通过当前可用性检查，来源显示为已重置。重置是为了重建记忆，抹掉内容靠清除。harness 会把窗口里已知的来源挂到 assistant 片段和工具事件上，并在发出模型请求前检查这些来源；如果旧记忆让这些事件变得不可读或不可用，重置之后重建的窗口会缺掉所有用过记忆的 assistant 输出。

- Rejected: 像清除一样让这些事件不可读，在操作者用重置来擦除隐私内容时更好；像撤回一样让它们仍可读但通不过当前检查，在旧记忆的副本不能流进新记忆时更好。
- Wrong-call signal: 操作者重置记忆后，发现想忘掉的内容仍能从会话日志搜到，或被重建回记忆。

### 模块的 era 写进分区名

存储内核按「模块.era.名称」给每个模块的分区命名。重置记忆时先建好新 era 的空分区，用一次提交切换记忆模块的当前 era，再删除旧 era 的分区；打开存储时会删除不属于当前 era 的分区，中断的重置因此会接着清理。这样重置不必逐键删除，记忆模块的键格式也不用改。

- Rejected: 在每个键前加上 era，再按前缀分批删除旧键，在一个模块重置时必须保留部分数据时更好。
- Wrong-call signal: 打开存储时分区数量或删除旧分区的耗时明显增长。

## Not this

- 会话头记录、fork 和带修订号的会话列表，包括子运行的会话与父会话的关联及其类型。
- 子调用：工具执行期间发出的工具调用与它的父调用之间的关联。
- 解析 assistant 载荷：只出现在载荷里、没有记下工具调用事件的工具请求，由 harness 在派生对话时处理。
- 单独记录每次模型请求的请求头。
- 按轮次或步骤查询的读取接口。
- 对话缓存。
- 把运行状态放进同一存储。
- 只重置会话模块。
- 决定记忆模块的内部模型。
- 读取输入流期间释放写锁。
- 迁移旧格式的数据。
